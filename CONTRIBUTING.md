# Contributing to Vaultly

Thanks for helping. The most useful thing you can do is tell us when something on the site is
**wrong** — a price, a discount, a term — because every number comes from a seller's own page and
sellers change them without notice.

## Report a wrong price or term

Open an issue with the **Wrong price or term** template. Include:

- the brand and the seller (GyFTR, Woohoo, Amazon, CashKaro);
- what Vaultly shows, and what the seller's own page shows;
- a link to that seller page, and when you looked.

That's usually enough to find the rule that misread it.

## Set up

```bash
npm install
npm run scrape:fast   # GyFTR + Woohoo -> public/catalog.json (~2 min)
npm run dev           # http://localhost:5173
```

Node 22 or newer. Amazon is read through a real Chrome via Playwright, so `npm run scrape` needs
Chrome or Edge installed.

Accounts work in development without any setup: they're kept in `.data/dev-accounts.json`, which
is git-ignored.

## Before you open a pull request

```bash
npx tsc -b       # strict type-check
npm run build    # production build
```

Both run in CI. If you changed how a seller is read, run the scraper for that seller and look at
what changed in `public/catalog.json` — a rule that fixes one brand can quietly change fifty.

Please **don't commit a hand-edited `public/catalog.json`**. It's generated by the scraper and
refreshed daily by `.github/workflows/refresh-prices.yml`; fix the reader, not the output.

## Where things live

| To change… | Look in |
| --- | --- |
| How a seller is read | `scripts/sources/<seller>.mjs` |
| What the four key facts say, and which sentences they're read from | `scripts/lib/facts.mjs` |
| How listings merge across sellers | `scripts/lib/build.mjs` |
| The comparison UI | `src/components/SitePanel.tsx`, `KeyFactsCompare.tsx` |
| Accounts and saved cards | `server/auth-core.mjs`, `src/context/` |

### Adding a seller

Create `scripts/sources/<name>.mjs` exporting `PLATFORM`, `listBrandUrls()` and
`fetchBrand({ slug, url })` returning `{ key, name, logo, offer }`, then register it in the
`SOURCES` map in `scripts/scrape.mjs`.

### Teaching the key-fact rules a new phrasing

Each rule in `scripts/lib/facts.mjs` is a regular expression plus the answer it produces. When
adding one:

1. Quote a real sentence from a seller in a comment.
2. Check it doesn't read the *opposite* sentence the same way — "CAN be used multiple times" and
   "CANNOT be used multiple times" differ by one word.
3. Run it over the whole catalog and read what changed. Anything that flips from a correct answer
   to a wrong one is a bug in the rule.

## Ground rules for sellers

- Read only what's publicly served to any visitor.
- Go slowly, and stop when a seller blocks you. A CAPTCHA or "click to continue" page is a *no* —
  report it as blocked, never click through it and never try to get around it.
- Don't read anything that needs a login or defeats an app's protections.
